# SQL Server Data Migration Plan

## Goal

Move the local forum data from the existing SQLite export into SQL Server using a repeatable file-based workflow.

## Recommended Flow

1. Export the local data to JSON.
2. Create the SQL Server schema.
3. Generate a SQL insert script from the JSON export.
4. Run the insert script in SSMS or `sqlcmd`.
5. Verify row counts and spot-check API behavior.

## Files In This Repo

- `export-to-json.js`
  Exports all local forum tables into `forum-export.json`.
- `sqlserver-migration.sql`
  Creates the SQL Server schema using `discussion_forum_*` table names.
- `generate-sqlserver-inserts.js`
  Generates a runnable SQL Server data script from `forum-export.json`.
- `sqlserver-data-insert.sql`
  Output artifact generated by the script above.

## Data Load Order

The import order preserves foreign-key dependencies:

1. `Users`
2. `Tags`
3. `Questions`
4. `QuestionTags`
5. `Answers`
6. `Comments`
7. `Votes`
8. `Media`
9. `Bookmarks`
10. `Notifications`
11. `LinkedQuestions`
12. `UserTags`
13. `SearchSuggestions`
14. `QuestionViews`

## Execution Steps

### 1. Export from local DB

```powershell
node export-to-json.js
```

### 2. Create schema in SQL Server

Open `sqlserver-migration.sql`, replace `YourForumDatabase`, then run it in SSMS.

### 3. Generate insert script

```powershell
node generate-sqlserver-inserts.js --database discussion_forum
```

Optional custom paths:

```powershell
node generate-sqlserver-inserts.js --input forum-export.json --output sqlserver-data-insert.sql --database discussion_forum
```

### 4. Run the generated script

In SSMS:

- Open `sqlserver-data-insert.sql`
- Confirm the `USE [YourDatabase]` target
- Execute

Or with `sqlcmd`:

```powershell
sqlcmd -S . -d discussion_forum -E -i sqlserver-data-insert.sql
```

## Why This Path Is Useful

- No live app-to-DB migration code is required during the data move.
- The generated script is reviewable before execution.
- IDs are preserved with `IDENTITY_INSERT` for identity tables.
- The script can be archived as a migration artifact.

## Verification Checklist

- Confirm row counts for each `discussion_forum_*` table.
- Check a few foreign-key joins manually:
  - questions to users
  - answers to questions
  - comments to answers/questions
  - bookmarks to users/questions
- Open the API and verify:
  - `/api/v1/questions`
  - `/api/v1/questions/1`
  - `/api/v1/questions/1/answers`
  - `/api/v1/stats`

## Notes

- The generated script assumes `forum-export.json` matches the SQL Server schema columns.
- The generated script is intended for an empty target schema. If rows already exist, expect duplicate key failures.
- If you regenerate local data, rerun the generator to produce a fresh SQL insert script.
- If the target SQL Server uses a different database name, pass `--database`.
